# Editable agency previews — October 6, 2026

Sending Links now use `/preview/<agency>` and an agency-specific, case-sensitive preview password. RP staff can copy the link and read the password in `/admin` or the staff gallery. Existing signed `/send/<agency>/<token>` links remain valid entry points, but now redirect to the password screen. Their old cookies do not authorize editing.

After sign-in, recipients can edit officials, biographies and inline images, portraits, management, contact visibility, layout preferences, representation and validated district maps. Save applies immediately to all four preview layouts and biographies. It never publishes to residents. The gallery, designs, biography pages and editor display Prepared default or Edited preview. The RP staff hub also identifies agencies with saved client edits. Return to default confirms before resetting the whole agency preview. Changes are shared among that agency's password holders, not attributed to an individual account.

The default is a snapshot of the agency's published preparation when its preview is first opened. Existing live drafts are excluded. Draft, published and baseline preview records live in `client_preview_state` inside the agency database; preview audit and image records use separate tables, and image files use `preview-uploads`. Reset restores that snapshot with an optimistic revision check. Uploaded trial images remain private; no live content, live image, MFA account or RP website CMS content is overwritten or reset.

Only `/api/previews/<agency>/...` selects the authenticated preview write scope. It permits content editing, image uploads, address lookup, reset and logout. Live publishing and account operations are rejected. Live agency APIs continue to require their existing MFA/RP sandbox authorization. Password login is rate limited, same-origin protected, and creates a signed HttpOnly cookie valid for seven days. Agency binding, expiry, password changes and preview-revision changes are checked server-side.

Default passwords are defined in the server module `lib/client-preview-token.ts`. To replace one, configure `AGENCY_PREVIEW_PASSWORD_<SLUG_UPPER_UNDERSCORES>` in Railway; the staff sending panel follows this value and existing sessions become invalid. The existing `AGENCY_PREVIEW_REVISION_<SLUG_UPPER_UNDERSCORES>` also revokes that agency's sessions/legacy sending links. Do not rotate APP_SECRET to manage a preview, because it also encrypts existing live MFA secrets.

Validation: unit coverage checks token scope, expiry, rotation and legacy rejection; baseline isolation, shared saves, reset conflicts, original draft preservation and denied publishing. HTTP coverage exercises every available agency, all four designs, sanitized biographies, portrait upload, reset, staff-route denial, cross-agency denial, CSRF and live-write denial. Browser QA covers password entry, editing a name, Edited preview status and Return to default. Tests use disposable local data, never production content.
